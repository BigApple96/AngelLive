# 安卓电视客户端与家庭 AI 操作指南

本目录是独立 Flutter 安卓 TV 兼容客户端。先读根 `AGENTS.md`、`PRODUCT.md`、本文件与 [安装调试手册](docs/HOME_AI.md)。遵守根文件的凭据保护、平台中立、测试诚信和工作区保护要求。

## 工作范围

- 客户端代码仅在本目录，构建流程在 `.github/workflows/android-tv.yml`。保持 Apple 宿主、共享 Swift 包和原有 CI 的边界；本任务不要求运行 Xcode。
- Android 设备通过 ADB 操作；Apple 的 Device Hub 命令不能用于 Android。若任务转为 Apple 端，回到根文档对应路由。
- 具体电视地址、`getprop` 实测型号、签名指纹和测试房间放忽略的 `tv.local.json` / `.local/`，从模板复制后配置。禁止猜 IP、扫描内网或沿用另一个任务的 ADB serial。
- 插件源由私有构建配置或应用设置提供；平台差异只放插件，不为特定来源硬编码解析、凭据字段或重连分支。

## 已授权安装调试时的执行顺序

1. 检查 Git 状态和用户最新要求；用户叫停立即停止设备操作。一次只有一个操作者控制电视，不操作用户正在观看的页面。
2. 运行 `python scripts/tv.py connect`、`doctor`。首次网络调试/ADB RSA 授权只能由人在电视端完成，授权缺失时明确指出这一步，继续能独立完成的构建或日志分析。
3. 核对明确的仓库、分支、成功 workflow run、源码 SHA、APK 校验值、实际签名、包名、版本、电视型号与 ABI。推荐用 `github-install --run-id <明确的运行编号>`；不使用未经检查的“最新 APK”。
4. 安装只用保留数据的替换安装。脚本拒绝签名/目标不匹配；不以卸载、`pm clear`、降级或重置插件/账号“修复”失败。确需删除数据必须先说明具体数据影响并取得用户明确授权。
5. 启动后捕获原尺寸截图，读取实际界面，再发送一个方向键/确认键；`key` 会自动保存动作后的截图。不要按猜测坐标操作或盲目连续确认。
6. 登录、订阅导入及播放必须分别验证。网络/解析错误、播放器错误、掉帧、缓冲、源站结束、后台恢复分别定位；不把普通请求失败判为直播结束。
7. 每次源码变化重新构建、安装并取证，旧截图和旧版本日志不作为本轮成功证据。真实电视证据保存在忽略的 `runs/`；不要提交截图、账号、私有插件或未审核日志。
8. 交付记录成功 run URL、源码 SHA、APK SHA-256、签名、设备实测信息、安装版本、测试动作与观察结果；分别说明构建、安装、UI、起播和持续播放是否通过。

## 代码与本地检查

```shell
flutter pub get --enforce-lockfile
flutter analyze --no-pub
flutter test --no-pub
python -m unittest discover -s scripts/tests -v
flutter build apk --release --no-pub --target-platform android-arm,android-arm64
```

Flutter 3.38.3、JDK 17，其他锁定版本见 README 和工作流。没有签名配置时 CI 使用不同包名的预览版，不能把预览版当作已安装正式包的升级。部分平台或内容需要首版未接入的能力，见 [协议范围](docs/PLUGIN_COMPATIBILITY.md)。

## 推荐的真实播放验收

使用用户指定、当时确认开播且允许访问的房间。先记录起播时间，连续播放至少 10 分钟，检查音画、缓冲、内存、遥控焦点、清晰度/线路切换和返回行为。需要断网/待机实验时先确认不影响用户当前使用，并记录恢复前后证据。没有实时音画观察时，只能报告进程/日志/画面状态，不能称“长时间播放流畅”。
